We were building **BeautyFind**, a Hebrew RTL beauty & wellness directory for Israel. The scope is 14 service categories, 7 regions (צפון, חיפה, שרון, גוש דן, ירושלים, שפלה, דרום) and 60+ cities.

**Design decisions locked in:**

- **Language & type**: Full RTL, Frank Ruhl Libre (headlines) + Assistant UI (body) with negative letter-spacing. Navy/teal palette, card vocabulary.
- **Geography**: 7-region selector with dependent city selection; region tabs on business rails, region rows on directory pages.
- **CTAs**: WhatsApp, click-to-call, Waze navigation, book online, contact form, Instagram.
- **Images**: Lazy-loaded, `aspect-ratio: 16/10`, absolute positioning so portrait-intrinsic images don't stretch grids. 19 generated by Higgsfield (Recraft V4.1), localized as sized JPEGs.
- **Tech rules**: `matchMedia` for breakpoints not width measurement. Explicit grid tracks so cards never leave empty bordered cells. `overflow-x:clip` not `hidden` so sticky positioning works. Sticky elements only engage if children are the pinned target and viewport-height-constrained. `loading="lazy"` on every templated `<img>`.
- **Israeli market**: Prices in ₪, `לא כולל מע״מ`. Hours ראשון–שישי with שבת סגור. Injectables are physician-only (אחריות רפואית), not קוסמטיקאית work. Treatments aren't in הסל.

**Current state:** Six pages complete and live:

1. **BeautyFind Homepage.dc.html** — hero search, 14 category grid, region/city scroller with clinic cards, E-E-A-T reviews, Israel map in light-cartography perspective frame.
2. **BeautyFind Business Profile.dc.html** — gallery, identity block, services accordion with per-variant ₪ pricing, reviews, team, hours (ראשון–שישי), FAQ, sticky קביעת תור sidebar with Google rating at bottom, Waze nav.
3. **BeautyFind Get Listed.dc.html** — ₪149/month pricing, feature cards, outcomes, FAQ, dark CTA.
4. **BeautyFind Directory.dc.html** — city listing, 4-up stats, live filter/sort, business cards, local guide with median-price table, sibling links, blog row.
5. **BeautyFind Search.dc.html** — split search bar, faceted filter rail (7 regions, 14 treatments, ₪₪₪ price tiers, languages, פתוח בשישי), sort, list/grid/map views, live facet counts.
6. **BeautyFind Blog.dc.html** — 12 Hebrew guides tagged by city and treatment, dual-tag filter, search, load-more.
7. **BeautyFind Treatment Category.dc.html** — answer-first hero with stats, sub-treatment list, median price table (per unit / per mL), top businesses with region tabs, city links, FAQ, sibling categories, in-category guides. 14 categories keyed by slug in a `CONTENT` map.

_[tool: ready_for_verification]_

**Root cause:** every responsive grid was driven by a JS `matchMedia` read, and the host iframe fires no `resize` inside the frame after it settles its width — so the state stayed frozen at the construct-time (narrow) value no matter how many re-reads I scheduled.

**Fix (one decisive change, both pages):** all breakpoints now live in CSS media-query custom properties in `<helmet>` (`--ticker-cols`, `--two-cols`, `--three-cols`, `--chart-cols`, `--body-cols`, `--rail-pos`, …) consumed as `grid-template-columns:var(…)`. No JS timing involved — correct on first paint. The desktop-only column header row is now a `[data-wide-only]` CSS rule instead of a JS-gated `sc-if`, and the mega-menu/mobile-drawer gates dropped their `desk` dependency (the triggers are already CSS-gated). JS now only owns real state: menus, FAQ, filters, scroll progress and active TOC. The unresolved-hole warnings are gone too — the article's one price table reads top-level `priceHead`/`priceRows`.
